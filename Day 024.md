# 100 Days of Cloud Azure - Day 024: Securing Virtual Machine SSH Access

## Scenario

The Nautilus DevOps team needs to deploy a new Azure Virtual Machine and configure secure, passwordless SSH access from the `azure-client` landing host.

Instead of using password authentication, an SSH key pair generated on the client will be used to authenticate the `azureuser` account on the Azure VM.

## Requirement

Configure the environment with the following requirements:

- **VM Name:** `nautilus-vm`
- **Region:** `West US`
- **VM Size:** `Standard_B1s`
- **Admin Username:** `azureuser`
- **Authentication:** SSH public key
- **SSH Client:** `azure-client`
- **Access:** Passwordless SSH
- **Method:** Azure Portal or Azure CLI

The SSH public key from `azure-client` must be associated with the `azureuser` account on `nautilus-vm`.

## Implementation

### 1. Identify the Existing Resource Group

List the available resource groups:

```bash
az group list --output table
```

Store the existing lab resource group:

```bash
RG="<resource-group-name>"
```

Verify:

```bash
echo "$RG"
```

---

## 2. Check for an Existing SSH Key Pair

Before generating a new key, check whether one already exists on `azure-client`:

```bash
ls -l ~/.ssh/id_rsa ~/.ssh/id_rsa.pub
```

If both files exist, the existing key pair can be used.

The SSH key pair consists of:

```text
~/.ssh/id_rsa      → Private key
~/.ssh/id_rsa.pub  → Public key
```

If the key does not exist, generate one:

```bash
ssh-keygen -t rsa
```

Accept the default location:

```text
/root/.ssh/id_rsa
```

Verify the public key:

```bash
cat ~/.ssh/id_rsa.pub
```

> The private key must remain on `azure-client`. Only the public key should be installed on the VM.

---

## 3. Create the Azure Virtual Machine

Create the VM in the required `West US` region:

```bash
az vm create \
  --resource-group "$RG" \
  --name nautilus-vm \
  --location westus \
  --image Ubuntu2204 \
  --size Standard_B1s \
  --admin-username azureuser \
  --ssh-key-values ~/.ssh/id_rsa.pub \
  --storage-sku Standard_LRS \
  --os-disk-size-gb 30
```

The explicit disk configuration keeps the VM within the lab's storage restrictions:

```text
Disk Type: Standard_LRS
Disk Size: 30 GB
```

## Verification Before SSH

Verify that the VM was successfully created:

```bash
az vm show \
  --resource-group "$RG" \
  --name nautilus-vm \
  --show-details \
  --output table
```

Confirm:

```text
Name:        nautilus-vm
Location:    westus
Size:        Standard_B1s
Power State: VM running
```

Retrieve the Public IP:

```bash
PUBLIC_IP=$(az vm show \
  --resource-group "$RG" \
  --name nautilus-vm \
  --show-details \
  --query publicIps \
  --output tsv)
```

Verify:

```bash
echo "$PUBLIC_IP"
```

---

## 4. Verify SSH Network Access

Confirm that the VM's Network Security Group permits inbound SSH traffic on TCP port `22`.

List the VM's NSG rules if required:

```bash
az network nsg list \
  --resource-group "$RG" \
  --output table
```

The required network path is:

```text
azure-client
     │
     │ TCP/22
     ▼
Public IP
     │
     ▼
Network Security Group
     │
     │ Allow SSH/22
     ▼
nautilus-vm
     │
     ▼
sshd
     │
     ▼
azureuser
```

---

## 5. Verify Passwordless SSH

From `azure-client`, connect to the VM:

```bash
ssh -i ~/.ssh/id_rsa azureuser@"$PUBLIC_IP"
```

The connection should succeed using the SSH private key without requesting the `azureuser` password.

After connecting, verify the identity:

```bash
whoami
```

Expected:

```text
azureuser
```

Verify the hostname:

```bash
hostname
```

Expected:

```text
nautilus-vm
```

Exit the VM:

```bash
exit
```

## Result

Passwordless SSH access was successfully configured:

```text
azure-client
│
├── ~/.ssh/id_rsa
│       Private Key
│
└── ~/.ssh/id_rsa.pub
        Public Key
             │
             ▼
        TCP Port 22
             │
             ▼
        nautilus-vm
             │
             ▼
        azureuser
             │
             ▼
     authorized_keys
```

The `azure-client` host can securely connect to `nautilus-vm` as `azureuser` using SSH public-key authentication without requiring a password.

## Key Takeaways

- SSH key authentication uses a **public/private key pair**.
- The private key remains on the client and must be protected.
- The public key is installed in the remote user's SSH configuration.
- Azure places the authorized public key into the appropriate configuration for the VM administrator account during provisioning.
- `--ssh-key-values` allows an existing client public key to be supplied when creating a VM through Azure CLI.
- Passwordless SSH does not mean authentication is bypassed; possession of the corresponding private key provides the authentication.
- SSH connectivity requires both successful key authentication and network access to TCP port `22`.
- The dependency path should always be validated end-to-end:

  ```text
  Private Key
      ↓
  Public IP
      ↓
  NSG TCP/22
      ↓
  sshd
      ↓
  authorized_keys
      ↓
  azureuser
  ```

- Private SSH keys should never be copied to the server, committed to Git, or shared with other users.
- In production environments, SSH/22 should generally be restricted to trusted administrative networks or controlled access solutions rather than exposed broadly to the internet.

# 100 Days of Cloud Azure - Day 004: Create Virtual Network via Azure CLI

## Scenario

The Nautilus DevOps team is gradually migrating infrastructure to Microsoft Azure. As part of the network foundation, an Azure Virtual Network (VNet) needs to be created for future cloud resources.

## Requirement

Create an Azure Virtual Network with the following configuration:

- **VNet Name:** `devops-vnet`
- **Region:** `westus`
- **Address Space:** Any valid IPv4 CIDR block
- **Method:** Azure CLI
- Use the existing resource group.

## Implementation

First, identify the existing resource group:

```bash
az group list --output table
```

Store the resource group name for easier reuse:

```bash
RG="<resource-group-name>"
```

Create the VNet using the private IPv4 CIDR block `10.0.0.0/16`:

```bash
az network vnet create \
  --resource-group "$RG" \
  --name devops-vnet \
  --location westus \
  --address-prefixes 10.0.0.0/16
```

## Verification

Verify that the VNet was created:

```bash
az network vnet show \
  --resource-group "$RG" \
  --name devops-vnet \
  --output table
```

Verify the configured address space:

```bash
az network vnet show \
  --resource-group "$RG" \
  --name devops-vnet \
  --query "{Name:name,Location:location,AddressSpace:addressSpace.addressPrefixes}" \
  --output table
```

Expected configuration:

```text
Name         Location    AddressSpace
-----------  ----------  ------------
devops-vnet  westus      10.0.0.0/16
```

## Result

The `devops-vnet` Virtual Network was successfully created in the `westus` region using the Azure CLI with the IPv4 address space `10.0.0.0/16`.

## Key Takeaways

- Azure VNets provide private network isolation for Azure resources.
- `az network vnet create` can create a VNet directly from the CLI.
- CIDR notation defines the available IP address range within the VNet.
- Private RFC1918 address ranges such as `10.0.0.0/16` are commonly used for internal cloud networks.
- Always identify the existing resource group before creating resources rather than assuming its name.
- Verify the deployed resource after creation to ensure its name, region, and address space match the requirements.

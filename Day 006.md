# 100 Days of Cloud Azure - Day 006: Create a Subnet in Azure Virtual Network

## Scenario

The Nautilus DevOps team is continuing its incremental migration to Microsoft Azure. As part of the network infrastructure setup, a Virtual Network (VNet) and a subnet need to be created to provide an isolated network segment for future Azure resources.

## Requirement

Create the Azure networking resources with the following configuration:

- **VNet Name:** `datacenter-vnet`
- **VNet IPv4 Address Space:** `10.0.0.0/16`
- **Subnet Name:** `datacenter-subnet`
- **Region:** `Central US`
- **Method:** Azure Portal (GUI)

## Implementation

1. Sign in to the **Azure Portal**.
2. Search for **Virtual networks**.
3. Open **Virtual networks** and click **Create**.
4. Under the **Basics** tab:
   - Select the existing **Subscription**.
   - Select the existing **Resource Group**.
   - Set **Virtual network name** to:

   ```text
   datacenter-vnet
   ```

   - Set **Region** to:

   ```text
   Central US
   ```

5. Open the **IP Addresses** tab.
6. Configure the VNet IPv4 address space as:

   ```text
   10.0.0.0/16
   ```

7. Under **Subnets**, create a subnet with the name:

   ```text
   datacenter-subnet
   ```

8. Assign the subnet an IPv4 range that falls within the VNet's `10.0.0.0/16` address space, for example:

   ```text
   10.0.0.0/24
   ```

9. Save the subnet configuration.
10. Leave the remaining settings at their defaults unless required by the lab.
11. Click **Review + create**.
12. Confirm that Azure validation passes.
13. Click **Create**.

## Verification

After deployment:

1. Open **Virtual networks** in the Azure Portal.
2. Select `datacenter-vnet`.
3. Verify the VNet configuration:
   - **Region:** `Central US`
   - **Address Space:** `10.0.0.0/16`
4. Navigate to **Settings → Subnets**.
5. Verify that `datacenter-subnet` exists.
6. Confirm that its subnet CIDR falls within the VNet's `10.0.0.0/16` address space.
7. Run the KodeKloud challenge validation.

## Result

The Azure network infrastructure was successfully created with:

- VNet: `datacenter-vnet`
- VNet CIDR: `10.0.0.0/16`
- Subnet: `datacenter-subnet`
- Region: `Central US`
- Azure Portal used for deployment

## Key Takeaways

- A VNet defines the overall private network boundary for Azure resources.
- Subnets divide a larger VNet address space into smaller network segments.
- A subnet CIDR must fall within the address space assigned to its parent VNet.
- Using `10.0.0.0/16` for the VNet provides room to create multiple smaller subnets as the environment grows.
- Subnet planning is important because application, database, management, and other workloads can later be separated into different network segments.
- Always verify the VNet and subnet address ranges before deploying workloads to avoid overlapping network ranges.

# 100 Days of Cloud Azure - Day 020: Deploy Azure Resources Using ARM Template

## Scenario

The Nautilus DevOps team is moving toward Infrastructure as Code (IaC) for Azure deployments.

An existing Azure Resource Manager (ARM) template needs to be modified to deploy a Virtual Network with the required name, address space, and resource tags. After updating the template, the infrastructure must be deployed using the Azure CLI.

## Requirement

Modify the existing ARM template:

```text
/root/arm-templates/vnet-deployment-template.json
```

Apply the following changes:

- **VNet Name:** `arm-vnet-nautilus`
- **displayName Tag:** `arm-vnet-nautilus`
- **Address Prefix:** `192.168.0.0/16`
- Add the following tag:

```text
Environment = KKE-nautilus
```

After modifying the template:

- Identify the existing KodeKloud resource group.
- Validate the ARM template.
- Deploy the template using Azure CLI.
- Verify that the VNet was created successfully.

## Implementation

### 1. Identify the Resource Group

First, find the existing resource group:

```bash
az group list --query '[].name' --output table | grep 'kml'
```

Save the returned resource group name for the deployment:

```bash
RG="<resource-group-name>"
```

### 2. Inspect the Existing ARM Template

Navigate to the ARM template directory:

```bash
cd /root/arm-templates
```

Verify the template exists:

```bash
ls -l vnet-deployment-template.json
```

Inspect the current configuration before modifying it:

```bash
cat vnet-deployment-template.json
```

This establishes the original state before making changes.

### 3. Modify the ARM Template

Edit the template:

```bash
vi vnet-deployment-template.json
```

Update the Virtual Network resource so that the required portions resemble:

```json
{
  "type": "Microsoft.Network/virtualNetworks",
  "name": "arm-vnet-nautilus",
  "tags": {
    "displayName": "arm-vnet-nautilus",
    "Environment": "KKE-nautilus"
  },
  "properties": {
    "addressSpace": {
      "addressPrefixes": [
        "192.168.0.0/16"
      ]
    }
  }
}
```

Preserve the rest of the existing ARM template structure and properties unless the challenge specifically requires them to be changed.

### 4. Verify the Changes Before Deployment

Confirm the required values exist in the template:

```bash
grep -nE 'arm-vnet-nautilus|192\.168\.0\.0/16|Environment|KKE-nautilus' \
  vnet-deployment-template.json
```

Optionally verify that the JSON syntax is valid:

```bash
python3 -m json.tool vnet-deployment-template.json > /dev/null
```

No output indicates valid JSON syntax.

### 5. Validate the ARM Deployment

Before creating resources, validate the ARM template against Azure:

```bash
az deployment group validate \
  --resource-group "$RG" \
  --template-file /root/arm-templates/vnet-deployment-template.json
```

Resolve any validation errors before proceeding with the actual deployment.

### 6. Deploy the ARM Template

After validation succeeds, deploy the template:

```bash
az deployment group create \
  --resource-group "$RG" \
  --template-file /root/arm-templates/vnet-deployment-template.json
```

Wait until the deployment completes successfully.

## Verification

Verify that the Virtual Network exists:

```bash
az network vnet show \
  --resource-group "$RG" \
  --name arm-vnet-nautilus \
  --output table
```

Verify the VNet address space:

```bash
az network vnet show \
  --resource-group "$RG" \
  --name arm-vnet-nautilus \
  --query "addressSpace.addressPrefixes" \
  --output table
```

Expected:

```text
192.168.0.0/16
```

Verify the tags:

```bash
az network vnet show \
  --resource-group "$RG" \
  --name arm-vnet-nautilus \
  --query "tags" \
  --output json
```

Expected configuration:

```json
{
  "Environment": "KKE-nautilus",
  "displayName": "arm-vnet-nautilus"
}
```

Finally, run the KodeKloud challenge validation.

## Result

The ARM template was successfully modified and deployed through the Azure CLI.

The resulting Virtual Network contains the required configuration:

```text
ARM Template
    │
    └── Microsoft.Network/virtualNetworks
            │
            ├── Name: arm-vnet-nautilus
            ├── Address Space: 192.168.0.0/16
            │
            └── Tags
                 ├── displayName = arm-vnet-nautilus
                 └── Environment = KKE-nautilus
```

## Key Takeaways

- ARM templates provide a declarative Infrastructure as Code approach for deploying Azure resources.
- Instead of manually describing each creation step, the template defines the desired final state of the infrastructure.
- `az deployment group validate` provides a safer validation step before making changes to Azure resources.
- `az deployment group create` performs a resource-group-scoped ARM deployment.
- JSON syntax validation and Azure deployment validation solve different problems: valid JSON does not necessarily mean the ARM configuration is valid.
- Existing templates should be inspected before modification so that only the required properties are changed.
- Resource tags can be declared directly within an ARM template, helping maintain consistent metadata through automated deployments.
- Infrastructure as Code makes deployments repeatable, reviewable, and easier to maintain than relying exclusively on manual portal configuration.

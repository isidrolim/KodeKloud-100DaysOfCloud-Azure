# 100 Days of Cloud Azure - Day 021: Assigning Public IP to Virtual Machines

## Scenario

The Nautilus Development Team requires a new Azure Virtual Machine to host an application that needs a stable public IP address.

The VM must use SSH key authentication, and a **Static Public IP** must be associated with it so that the application's public endpoint remains consistent.

## Requirement

Create and configure the following Azure resources:

- **Virtual Machine:** `devops-vm`
- **Operating System:** Any available Ubuntu image
- **VM Size:** `Standard_B1s`
- **Admin User:** `azureuser`
- **SSH Key:** Generate on the `azure-client` host
- **Private Key:** `~/.ssh/id_rsa`
- **Public Key:** `~/.ssh/id_rsa.pub`
- **Public IP Name:** `devops-pip`
- **Public IP Allocation:** Static
- Verify that the VM is accessible through SSH using the generated key.

## Implementation

### 1. Generate the SSH Key Pair

On the `azure-client` host, first check whether the default SSH key already exists:

```bash
ls -l ~/.ssh/id_rsa ~/.ssh/id_rsa.pub
```

If the key pair does not exist, generate an RSA SSH key pair using the default filename:

```bash
ssh-keygen -t rsa
```

When prompted for the location, accept the default:

```text
~/.ssh/id_rsa
```

Verify the generated files:

```bash
ls -l ~/.ssh/id_rsa*
```

The key pair consists of:

```text
~/.ssh/id_rsa      → Private key
~/.ssh/id_rsa.pub  → Public key
```

The private key remains on the client, while the public key will be associated with the Azure VM.

---

## 2. Create the Azure Virtual Machine

1. Sign in to the **Azure Portal**.
2. Navigate to:

   ```text
   Virtual machines → Create → Azure virtual machine
   ```

3. Select the existing:
   - Subscription
   - Resource Group

4. Configure the VM:

   ```text
   Virtual machine name: devops-vm
   Image:                Any available Ubuntu image
   Size:                 Standard_B1s
   ```

5. Under **Administrator account**, configure:

   ```text
   Authentication type: SSH public key
   Username:            azureuser
   SSH public key source:
                        Use existing public key
   ```

6. Display the public key on the `azure-client` host:

   ```bash
   cat ~/.ssh/id_rsa.pub
   ```

7. Copy the complete public key and paste it into the Azure Portal's **SSH public key** field.

> Never copy or upload `~/.ssh/id_rsa`. Only the `.pub` public key should be provided to Azure.

---

## 3. Configure the Static Public IP

During VM creation, navigate to the **Networking** configuration.

Configure the VM to use a Public IP and create a new Public IP resource named:

```text
devops-pip
```

Ensure the Public IP configuration uses:

```text
IP assignment/allocation: Static
```

Also ensure SSH access on TCP port `22` is permitted so that the VM can be reached from the Azure client.

Complete the VM configuration and select:

```text
Review + create
```

After validation succeeds, click:

```text
Create
```

Wait for the deployment to finish.

### Verify the VM

Navigate to:

```text

```

Confirm:

```text

```

### Verify the Public IP

Navigate to:

```text
Public IP addresses → devops-pip
```

Verify:

```text
Name:          devops-pip
Assignment:    Static
Associated to: devops-vm network interface
```

Record the assigned Public IP address:

```text
<PUBLIC-IP>
```

The network dependency path should now be:

```text
Internet
   │
   ▼
devops-pip
Static Public IP
   │
   ▼
VM Network Interface
   │
   ▼
devops-vm
```

### Verify SSH Connectivity

From the `azure-client` host, connect using the generated private key:

```bash
ssh -i ~/.ssh/id_rsa azureuser@<PUBLIC-IP>
```

After connecting, verify the system:

```bash
whoami
hostname
```

Expected identity:

```text
azureuser
```

Expected hostname:

```text
devops-vm
```

Exit the VM:

```bash
exit
```

## Key Takeaways

- Azure Public IP resources provide internet-routable addresses for Azure workloads.
- A **Static Public IP** maintains a consistent IP assignment instead of relying on a dynamically allocated address.
- For an Azure VM, the Public IP is associated through the VM's **network interface IP configuration**.
- SSH authentication uses two related keys: the **private key remains on the client**, while the **public key is installed on the server**.
- The private SSH key should never be uploaded to Azure or committed to source control.
- A Public IP alone does not guarantee SSH connectivity; TCP port `22` must also be permitted by the relevant Network Security Group.
- End-to-end SSH testing validates the complete path: Public IP → NIC → NSG → VM → SSH authentication.
- In production, direct SSH exposure to the internet should be restricted to trusted source networks or replaced with controlled administrative access such as Azure Bastion where appropriate.

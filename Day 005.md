# 100 Days of Cloud Azure - Day 005: Create a Virtual Network (IPv4) in Azure

## Scenario

The Nautilus DevOps team is preparing the network foundation for its migration to Microsoft Azure. As an initial step, a Virtual Network (VNet) needs to be created to provide private network connectivity for future Azure resources.

## Requirement

Create an Azure Virtual Network with the following configuration:

- **VNet Name:** `devops-vnet`
- **Region:** `East US`
- **IPv4 Address Space:** `192.168.0.0/24`
- **Method:** Azure Portal (GUI)
- Use the existing resource group.

## Implementation

1. Sign in to the **Azure Portal**.
2. Search for **Virtual networks** from the top search bar.
3. Open **Virtual networks** and click **Create**.
4. Under the **Basics** tab:
   - Select the existing **Subscription**.
   - Select the existing **Resource Group**.
   - Set **Virtual network name** to `devops-vnet`.
   - Set **Region** to `East US`.
5. Go to the **IP Addresses** tab.
6. Configure the IPv4 address space as:

   ```text
   192.168.0.0/24
   ```

7. Keep the remaining settings at their defaults unless required by the lab.
8. Click **Review + create**.
9. Verify that Azure validation passes.
10. Click **Create**.

## Verification

After deployment:

1. Open **Virtual networks**.
2. Select `devops-vnet`.
3. Verify:
   - **Name:** `devops-vnet`
   - **Region:** `East US`
   - **Address space:** `192.168.0.0/24`
4. Confirm the VNet deployment shows a successful state.
5. Run the KodeKloud challenge validation.

## Result

The `devops-vnet` Virtual Network was successfully created in Azure with:

- Region: `East US`
- IPv4 CIDR: `192.168.0.0/24`
- Existing Azure resource group
- Azure Portal used for deployment

## Key Takeaways

- Azure VNets provide private network boundaries for Azure resources.
- The VNet address space is defined using CIDR notation.
- `192.168.0.0/24` provides an address range within the VNet that can later be divided into subnets.
- Network address planning should be performed before deploying workloads to avoid overlapping address spaces.
- Always verify the VNet name, region, and CIDR before creating the resource.

# 100 Days of Cloud Azure - Day 008: Attach Managed Disk to Azure Virtual Machine

## Scenario

The Nautilus DevOps team is continuing its migration of services to Microsoft Azure. An existing managed disk needs to be attached to an existing Virtual Machine as a data disk.

## Requirement

Use the existing Azure resources:

- **Virtual Machine:** `devops-vm`
- **Managed Disk:** `devops-disk`
- **Region:** `South Central US`
- **Disk Purpose:** Data disk
- **Method:** Azure Portal (GUI)
- Ensure VM initialization has completed before submitting the task.

## Implementation

1. Sign in to the **Azure Portal**.
2. Search for **Virtual machines**.
3. Open the existing VM:

   ```text
   devops-vm
   ```

4. Confirm that the VM has completed initialization and is in a healthy/running state.
5. From the VM menu, navigate to:

   ```text
   Settings → Disks
   ```

6. Under **Data disks**, select **Attach existing disks**.
7. From the disk selection list, choose:

   ```text
   devops-disk
   ```

8. Keep the remaining disk attachment settings at their defaults unless required by the lab.
9. Click **Apply** or **Save** to update the VM configuration.
10. Wait for Azure to finish updating the Virtual Machine.

## Verification

After the update completes:

1. Open:

   ```text
   Virtual machines → devops-vm → Disks
   ```

2. Under **Data disks**, confirm that:

   ```text
   devops-disk
   ```

   is listed.

3. Verify that the disk is attached to:

   ```text
   devops-vm
   ```

4. Confirm that the VM remains operational after the disk attachment.
5. Run the KodeKloud challenge validation.

## Result

The existing Azure managed disk was successfully attached as a data disk:

- **VM:** `devops-vm`
- **Managed Disk:** `devops-disk`
- **Region:** `South Central US`
- **Disk Role:** Data disk
- **Deployment Method:** Azure Portal

## Key Takeaways

- Azure Managed Disks exist independently from Virtual Machines and can be attached as data disks.
- The VM's **Disks** configuration separates the OS disk from additional data disks.
- Attaching a managed disk at the Azure infrastructure layer does not necessarily make its filesystem immediately usable inside the operating system.
- A newly attached blank disk may still need to be initialized, partitioned, formatted, and mounted inside the guest OS.
- Existing disks containing data should be inspected before formatting to avoid accidental data loss.
- Always verify that the correct disk is being attached to the correct VM before applying the change.

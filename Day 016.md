# 100 Days of Cloud Azure - Day 016: Create a Private Azure Blob Storage Container

## Scenario

As part of the data migration process, the Nautilus DevOps team is moving application data into Microsoft Azure.

The team requires an Azure Storage Account containing a private Blob Storage container so that migrated data can be stored without anonymous public access.

## Requirement

Create the following Azure storage resources:

- **Storage Account:** `xfusionst847045049`
- **Blob Container:** `xfusion-blob-847045049`
- **Container Access Level:** Private
- **Method:** Azure Portal (GUI)
- Use the existing Azure subscription and resource group.

## Implementation

### 1. Create the Storage Account

1. Sign in to the **Azure Portal**.

2. Search for:

   ```text
   Storage accounts
   ```

3. Open **Storage accounts** and click:

   ```text
   Create
   ```

4. Under the **Basics** tab:
   - Select the existing **Subscription**.
   - Select the existing **Resource Group**.
   - Enter the storage account name:

   ```text
   xfusionst847045049
   ```

5. Select the appropriate region for the lab environment.

6. Keep the remaining settings at their defaults unless specified by the challenge.

7. Click:

   ```text
   Review + create
   ```

8. Confirm that Azure validation succeeds.

9. Click:

   ```text
   Create
   ```

10. Wait until the storage account deployment completes successfully.

## Create the Private Blob Container

1. Open the newly created storage account:

   ```text
   xfusionst847045049
   ```

2. Navigate to:

   ```text
   Data storage → Containers
   ```

3. Click:

   ```text
   + Container
   ```

4. Enter the container name:

   ```text
   xfusion-blob-847045049
   ```

5. Configure **Anonymous access level** as:

   ```text
   Private (no anonymous access)
   ```

6. Click:

   ```text
   Create
   ```

## Key Takeaways

- An Azure **Storage Account** provides the top-level namespace for Azure Storage services.
- Azure **Blob Storage** is designed for storing unstructured object data such as files, backups, logs, images, and application data.
- Blob containers organize objects, known as **blobs**, within a storage account.
- Setting the container access level to **Private** prevents anonymous access to the container and its blobs.
- Private does not mean nobody can access the data; authorized identities and applications can still access it using supported Azure authentication and authorization mechanisms.
- Storage account names must be globally unique in Azure.
- Storage account names use lowercase letters and numbers, while container names also have Azure naming restrictions.
- For production workloads, avoid enabling anonymous Blob access unless there is a specific business requirement.

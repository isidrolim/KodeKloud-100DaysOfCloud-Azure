# 100 Days of Cloud Azure - Day 014: Create a Managed Disk in Azure

## Scenario

The Nautilus DevOps team is continuing its incremental migration to Microsoft Azure. As part of the infrastructure preparation, the team needs to provision a managed disk that can later be used as persistent storage for Azure workloads.

## Requirement

Create an Azure Managed Disk with the following configuration:

- **Disk Name:** `xfusion-disk`
- **Disk Type:** `Standard_LRS`
- **Disk Size:** `2 GiB`
- **Resource Group:** Use the existing resource group
- **Method:** Azure Portal (GUI)

## Implementation

1. Sign in to the **Azure Portal**.

2. Search for:

   ```text
   Disks
   ```

3. Open the **Disks** service.

4. Click:

   ```text
   Create
   ```

5. Under the **Basics** tab, select the existing:
   - Subscription
   - Resource Group

6. Set the disk name to:

   ```text
   xfusion-disk
   ```

7. Configure the **Source type** as:

   ```text
   None
   ```

   This creates a new empty managed disk.

8. Under **Size**, select/configure the required storage type:

   ```text
   Standard HDD (locally-redundant storage)
   ```

   Azure represents this storage SKU as:

   ```text
   Standard_LRS
   ```

9. Configure the disk size as:

   ```text
   2 GiB
   ```

10. Keep the remaining settings at their defaults unless required by the lab.

11. Click:

   ```text
   Review + create
   ```

12. Confirm that Azure validation succeeds.

13. Click:

   ```text
   Create
   ```

14. Wait for the managed disk deployment to complete.

## Verification

After deployment:

1. Navigate to:

   ```text
   Azure Portal → Disks
   ```

2. Open:

   ```text
   xfusion-disk
   ```

3. Verify the following configuration:

   ```text
   Disk name:    xfusion-disk
   Disk size:    2 GiB
   Disk SKU:     Standard_LRS
   ```

4. Confirm that the provisioning state shows:

   ```text
   Succeeded
   ```

5. Since this task only requires disk creation, verify that no unnecessary VM attachment was performed.

6. Run the KodeKloud challenge validation.

## Result

The Azure Managed Disk was successfully created with the required configuration:

- **Disk:** `xfusion-disk`
- **Storage Type:** `Standard_LRS`
- **Capacity:** `2 GiB`
- **Deployment Method:** Azure Portal

The disk is now available as an independent Azure storage resource and can be attached to a compatible Virtual Machine when required.

## Key Takeaways

- Azure Managed Disks provide persistent block storage for Azure Virtual Machines.
- A managed disk exists as an independent Azure resource and does not have to be attached to a VM when it is created.
- `Standard_LRS` represents Standard HDD storage using locally redundant storage.
- LRS maintains redundant copies of data within a single Azure region for storage durability.
- Creating a blank managed disk and attaching a disk to a VM are separate operations.
- In production, disk performance, redundancy, capacity, and cost should be considered before selecting a storage SKU.
- Always validate the disk name, SKU, and capacity after deployment rather than relying solely on a successful deployment notification.

# 100 Days of Cloud Azure - Day 022: Configuring Instances with User Data

## Scenario

The Nautilus DevOps team needs to deploy a new Azure Virtual Machine that will operate as a web server for an application.

Instead of manually installing and configuring the web server after deployment, the VM should automatically install and start Nginx during its initial provisioning using a custom startup script.

The web server must also be accessible from the internet over HTTP.

## Requirement

Create an Azure Virtual Machine with the following configuration:

- **VM Name:** `datacenter-vm`
- **Operating System:** Any available Ubuntu image
- **Web Server:** Nginx
- **Configuration Method:** Custom Script / User Data
- **HTTP Port:** `80`
- **HTTP Source:** Internet
- **Method:** Azure Portal (GUI)

The startup script must:

- Install Nginx.
- Start the Nginx service.
- Ensure the web server is available after deployment.

## Implementation

### 1. Create the Virtual Machine

1. Sign in to the **Azure Portal**.

2. Navigate to:

   ```text
   Virtual machines → Create → Azure virtual machine
   ```

3. Select the existing:
   - Subscription
   - Resource Group

4. Configure the VM:

   ```text
   Virtual machine name: datacenter-vm
   Image:                Any available Ubuntu image
   ```

5. Configure the administrator account using the authentication method appropriate for the lab.

6. Keep the remaining VM configuration at its defaults unless required by the challenge.

---

## 2. Configure HTTP Network Access

During VM creation, navigate to the **Networking** configuration.

Ensure the VM has a Public IP address and configure the Network Security Group to permit:

```text
Source:           Internet
Protocol:         TCP
Destination Port: 80
Action:           Allow
```

The required network path is:

```text
Internet
   │
   │ TCP/80
   ▼
Public IP
   │
   ▼
Network Security Group
   │
   │ Allow HTTP/80
   ▼
datacenter-vm
   │
   ▼
Nginx
```

---

## 3. Configure the Startup Script

During VM creation, use the **Advanced** configuration to provide the custom data/user data script.

Use:

```bash
#!/bin/bash

apt-get update
apt-get install -y nginx

systemctl enable nginx
systemctl start nginx
```

The script performs the following automatically during provisioning:

```text
VM Starts
   │
   ▼
Ubuntu initializes
   │
   ▼
Startup script executes
   │
   ├── Update package information
   ├── Install Nginx
   ├── Enable Nginx at boot
   └── Start Nginx
```

> The script runs with elevated privileges during provisioning, so `sudo` is not required inside the startup script.

---

## 4. Deploy the VM

After configuring the VM, networking, and startup script:

1. Click:

   ```text
   Review + create
   ```

2. Confirm Azure validation succeeds.

3. Click:

   ```text
   Create
   ```

4. Wait for the VM deployment and initialization to complete.

## Verification

### Verify the VM

Navigate to:

```text
Virtual machines → datacenter-vm
```

Confirm that the VM shows:

```text
Status: Running
```

Record its Public IP address.

### Verify HTTP Connectivity

From a browser, access:

```text
http://<PUBLIC-IP>
```

The default Nginx page should be displayed.

Alternatively, from a terminal:

```bash
curl http://<PUBLIC-IP>
```

A successful response confirms the complete dependency path:

```text
Internet
   ↓
Public IP
   ↓
NSG allows TCP/80
   ↓
VM network interface
   ↓
Ubuntu
   ↓
Nginx running
   ↓
HTTP response
```

If shell access to the VM is available, Nginx can also be verified directly:

```bash
systemctl status nginx
```

The service should report:

```text
active (running)
```

Finally, run the KodeKloud challenge validation.

The web server is accessible from the internet over HTTP.

## Key Takeaways

- Startup scripts allow a VM to configure itself automatically during provisioning.
- This removes the need to manually SSH into every newly deployed server to perform basic software installation.
- Installing Nginx alone is not enough for external access; the complete dependency path from the internet to the application must work.
- An Azure NSG must permit inbound TCP port `80` for HTTP traffic to reach the web server.
- `systemctl enable nginx` configures Nginx to start automatically after future reboots.
- `systemctl start nginx` starts the service immediately.
- Successful VM deployment does not prove that the application works; application-level validation such as `curl http://<PUBLIC-IP>` verifies the actual success criterion.
- Automated bootstrap configuration is an important step toward repeatable and consistent infrastructure deployments.

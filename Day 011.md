# 100 Days of Cloud Azure - Day 011: Change Azure Virtual Machine Size Using Console

## Scenario

The Nautilus DevOps team is migrating infrastructure to Microsoft Azure. One of the existing Virtual Machines is experiencing increased workload demand and requires additional compute resources.

The VM needs to be resized to a larger instance size using the Azure Portal.

## Requirement

Modify the existing Azure VM with the following configuration:

- **Virtual Machine:** `nautilus-vm`
- **Region:** `East US`
- **Current Size:** `Standard_B1s`
- **New Size:** `Standard_B2s`
- **Final VM State:** `Running`
- **Method:** Azure Portal (GUI)

## Implementation

1. Sign in to the **Azure Portal**.

2. Search for:

   ```text
   Virtual machines
   ```

3. Open the existing VM:

   ```text
   nautilus-vm
   ```

4. Before making changes, verify:
   - The VM is located in `East US`.
   - The current VM size is `Standard_B1s`.

5. From the VM menu, navigate to:

   ```text
   Availability + scale → Size
   ```

   Depending on the Azure Portal layout, **Size** may also appear directly under the VM settings menu.

6. Review the available VM sizes.

7. Search for and select:

   ```text
   Standard_B2s
   ```

8. Review the new VM size before applying the change.

9. Click:

   ```text
   Resize
   ```

10. Wait for Azure to complete the resize operation.

> **Note:** Resizing a VM can cause a restart or temporary service interruption. In a production environment, this change should be performed during an approved maintenance window when downtime could affect users.

## Verification

After the resize operation completes:

1. Navigate to:

   ```text
   Virtual machines → nautilus-vm → Overview
   ```

2. Verify the VM size now shows:

   ```text
   Standard_B2s
   ```

3. Verify the VM location remains:

   ```text
   East US
   ```

4. Check the VM status and ensure it shows:

   ```text
   Running
   ```

5. If the VM is stopped after the resize operation, select:

   ```text
   Start
   ```

6. Wait until the VM returns to:

   ```text
   Running
   ```

7. Run the KodeKloud challenge validation.

## Result

The Azure Virtual Machine was successfully resized:

- **VM:** `nautilus-vm`
- **Region:** `East US`
- **Previous Size:** `Standard_B1s`
- **New Size:** `Standard_B2s`
- **Final State:** `Running`
- **Deployment Method:** Azure Portal

## Key Takeaways

- Azure VM sizes determine the compute resources available to a Virtual Machine, including vCPU and memory.
- VM resizing allows compute capacity to be adjusted as workload requirements change.
- Not every VM size is necessarily available for every region, availability zone, or existing VM configuration.
- Resizing can cause a VM restart or temporary downtime and should therefore be treated as a production-impacting change.
- Changing the VM size does not require rebuilding the entire Virtual Machine.
- After resizing, always verify both the **new VM size** and the **running state** rather than assuming the resize operation completed successfully.

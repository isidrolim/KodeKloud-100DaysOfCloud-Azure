# 100 Days of Cloud Azure - Day 007: Create a Public IP Address for Azure VM

## Scenario

The Nautilus DevOps team is continuing its incremental migration to Microsoft Azure. As part of the networking setup, a Public IP address needs to be provisioned so that it can be associated with an Azure resource such as a Virtual Machine.

## Requirement

Create an Azure Public IP address with the following configuration:

- **Public IP Name:** `datacenter-pip`
- **Resource Group:** Use the existing resource group
- **Method:** Azure Portal (GUI)
- **Remaining Settings:** Keep the defaults unless otherwise required

## Implementation

1. Sign in to the **Azure Portal**.
2. In the top search bar, search for:

   ```text
   Public IP addresses
   ```

3. Open **Public IP addresses**.
4. Click **Create**.
5. Under the **Basics** configuration:
   - Select the existing **Subscription**.
   - Select the existing **Resource Group**.
   - Set **Name** to:

   ```text
   datacenter-pip
   ```

6. Keep the remaining configuration at the default values unless the lab specifies otherwise.
7. Review the Public IP configuration.
8. Click **Review + create**.
9. Wait for Azure validation to complete.
10. Click **Create**.

## Verification

After deployment:

1. Navigate to **Public IP addresses**.
2. Open:

   ```text
   datacenter-pip
   ```

3. Verify that:
   - The resource name is `datacenter-pip`.
   - The provisioning state is successful.
   - The Public IP resource exists in the expected resource group.
   - An IP address has been allocated if the selected configuration allocates one immediately.

4. Run the KodeKloud challenge validation.

## Result

The Azure Public IP resource was successfully provisioned:

- **Public IP:** `datacenter-pip`
- **Deployment Method:** Azure Portal
- **Provisioning:** Successful

The Public IP is now available to be associated with an Azure networking resource such as a Virtual Machine network interface or load balancer.

## Key Takeaways

- An Azure Public IP is a separate networking resource that can be associated with resources requiring internet-facing connectivity.
- Creating a Public IP does not by itself expose a VM to the internet; it must be associated with the appropriate network interface or other Azure resource.
- Public IP addressing and Network Security Group rules serve different purposes: the Public IP provides addressing, while the NSG controls permitted network traffic.
- Production systems should only receive Public IP addresses when there is a genuine requirement for direct internet connectivity.
- Always verify the exact resource name and resource group before deployment to avoid creating resources in the wrong environment.

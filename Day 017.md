# 100 Days of Cloud Azure - Day 017: Create a Public Azure Blob Storage Container

## Scenario

As part of the data migration process, the Nautilus DevOps team is creating Azure storage resources for data that needs to be publicly accessible.

For this task, a new Azure Storage Account and Blob container must be created, with anonymous read access enabled for both the container and its blobs.

## Requirement

Create the following Azure storage resources:

- **Storage Account:** `datacenterst309520122`
- **Blob Container:** `datacenter-blob-309520122`
- **Container Access:** Public
- **Anonymous Read Access:** Enabled for containers and blobs
- **Method:** Azure Portal (GUI)

## Implementation

### 1. Create the Storage Account

1. Sign in to the **Azure Portal**.

2. Search for:

   ```text
   Storage accounts
   ```

3. Open **Storage accounts** and click:

   ```text
   Create
   ```

4. Under the **Basics** tab:
   - Select the existing **Subscription**.
   - Select the existing **Resource Group**.
   - Enter the storage account name:

   ```text
   datacenterst309520122
   ```

5. Select the appropriate region for the lab environment.

6. Keep the remaining settings at their defaults unless specified by the challenge.

7. Before creating the account, ensure anonymous Blob access is permitted in the storage account configuration if the option is available during creation.

8. Click:

   ```text
   Review + create
   ```

9. Confirm Azure validation succeeds and click:

   ```text
   Create
   ```

10. Wait for the storage account deployment to complete.

---

## 2. Enable Anonymous Blob Access

1. Open the newly created storage account:

   ```text
   datacenterst309520122
   ```

2. Navigate to:

   ```text
   Settings → Configuration
   ```

3. Locate:

   ```text
   Allow Blob anonymous access
   ```

4. Set it to:

   ```text
   Enabled
   ```

5. Click:

   ```text
   Save
   ```

> This storage-account setting permits individual containers to be configured for anonymous access. The container itself must still be configured with the required public access level.

---

## 3. Create the Public Blob Container

1. Inside the storage account, navigate to:

   ```text
   Data storage → Containers
   ```

2. Click:

   ```text
   + Container
   ```

3. Enter the container name:

   ```text
   datacenter-blob-309520122
   ```

4. Configure the anonymous access level to allow public read access to both the container and its blobs:

   ```text
   Container
   ```

5. Click:

   ```text
   Create
   ```

## Key Takeaways

- Azure anonymous Blob access is controlled at **two levels**: the storage account must permit anonymous access, and the individual container must have a public access level configured.
- A container configured with **Container** anonymous access permits anonymous read access to both the container and its blobs.
- This differs from **Blob** access, which permits anonymous reads of individual blobs but does not provide anonymous access to list the container contents.
- A **Private** container prevents anonymous access entirely.
- Storage account names must be globally unique within Azure.
- Public Blob containers should be used carefully because their contents may be accessible to anyone on the internet without authentication.
- Production storage should default to private access unless anonymous public access is an explicit application or business requirement.
